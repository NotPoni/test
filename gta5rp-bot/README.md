# GTA 5RP Family Bot

Заявки и обзвон, CAPT-меню с веткой, Инактив-панель, голосовые баллы + магазин,
личные кабинеты и `!setup`, который сам создаёт роли и каналы и привязывает их к командам.
Системы сборов (`/mcl`, `/zonewars`, `/сбор`) нет.

## Запуск
1. Python **3.10+**, затем `pip install -r requirements.txt` (нужен **discord.py ≥ 2.6** из-за Components V2 в CAPT-меню).
2. `.env.example` → `.env`, впишите `DISCORD_TOKEN` и `GUILD_ID`.
3. Developer Portal → Bot → включите **Server Members Intent** и **Message Content Intent**.
4. Пригласите бота с правом **Administrator**, роль бота — как можно выше.
5. `python main.py`, затем на сервере под админом: **`!setup`**

Логи пишутся в консоль; уровень задаётся `LOG_LEVEL`. База — `DB_PATH` (по умолчанию `data.db`).

### Если в списке остались старые команды (`/create-mcl`, `/create-capt`, `/sync`…)
Это команды **старого бота** (`Desktop\bot\bot.py`) с тем же токеном: Discord хранит их, пока их кто-то не удалит.
Новая версия при старте сама удаляет в Discord все команды, которых нет в её коде (в консоли будет
`Удалены устаревшие slash-команды: …`). После перезапуска нажмите **Ctrl+R** в Discord, чтобы клиент обновил список.
Если команда всё равно приходит — в консоли будет `Нажата устаревшая команда: …`, а в ответе подсказка обновить клиент.

## `!setup`
Для каждой роли/канала: уже привязанное → ID из `.env` → существующее по названию → создать. Повторный запуск безопасен.

| Команда | Действие |
|---|---|
| `!setup` | роли, категории, каналы, права, панели |
| `!setup force` | то же + пересобрать права (один раз после обновления, чтобы в #capt писали в ветках) |
| `!setup panels` | переотправить панели |
| `!setup status` | что к чему привязано |
| `!setup bind <ключ> <@роль/#канал>` | привязать вручную |
| `!panel apply\|support\|afk\|shifts\|shop\|cabinet\|rules` | панель в текущий канал |

| Категория | Каналы |
|---|---|
| 📌 ИНФОРМАЦИЯ | правила, новости, приветствие, **подать-заявку**, **поддержка** |

## Заявки
Панель в #подать-заявку: **RP+CAPT** (5 вопросов) и **RP** (3 вопроса). Создаётся `заявка-N` (видят заявитель и штаб),
заявитель получает роль «Подал заявку», пингуются High и Recruiter.
1. **Взять на рассмотрение** → кнопки **Принять / Отклонить / Обзвон / Обновить / Закрыть**.
2. **Принять**: +1 балл, роли семьи и Newbie, снимается «Подал заявку», ЛС кандидату, канал удаляется
   через 3 секунды (транскрипт HTML уходит в #лог-заявок).
3. **Отклонить**: причина → ЛС кандидату, транскрипт, канал удаляется.
4. **Обзвон**: выбор канала; если кандидат в голосовом — его перемещают, иначе приглашение в заявку и в ЛС.
5. **Закрыть**: транскрипт (файл только вам) / закрыть с логом / удалить канал.

Особенности, которые важно знать:
- Транскрипт теперь содержит **и текст, и embed'ы** — то есть сами ответы анкеты (раньше они терялись).
- Статус меняется атомарно: двойной клик по «Принять» не выдаст роли и баллы дважды.
- Если канал заявки удалили вручную, «зависшая» запись закрывается при следующей подаче.
- Текст панели — `texts.py` (`APPLY_INFO`).

## Инактив-панель
Панель «⚙️ Инактив-панель» с кнопками **AFK** (срок из списка или свой), **Инактив** (причина + дни, уходит на одобрение
в #логи-afk), **Вернулся**, **Модерация** (для сотрудников: снять статус у участника, обновить панель, запросы на инактив).
Роли AFK/Инактив ставятся и снимаются сами, список в панели обновляется. В #варны приходит предупреждение, если человек
сидит в голосовом с выключенным звуком дольше `AFK_WARN_MINUTES` без статуса (в игре Discord-бот это увидеть не может).

Необработанный запрос на инактив теперь **истекает сам** (раньше он навсегда блокировал новые запросы).

## CAPT
`/capt title:"ЗА ОСОБУ vs hated" start_time:"18:20"` — меню-контейнер + ветка; сотрудник реакциями ✅/❌ (или 1️⃣…9️⃣) формирует
состав, кнопка «Завершить» начисляет баллы (`CAPT_REWARD`). Завершение идемпотентно: повторное нажатие не начислит баллы ещё раз.
Список состава автоматически обрезается под лимит Components V2 (4000 символов), чтобы сообщение не падало с 400.

## Остальное
`/кадры` (цепочка Newbie → Main → Tier-2 → Tier-1), `/баллы`, `/топ`, магазин, кабинеты, модерация, анти-краш, `/spect`.
Оформление: `config.py`, `ui.py`, `texts.py`, `blueprint.py`.

## Что исправлено в этой версии
- **Заявки**: ответ на interaction уходил в уже удалённый канал (`404 Unknown Channel`) при «Принять/Отклонить/Закрыть»;
  транскрипт не содержал ответов анкеты; двойное принятие; зависшие записи.
- **Баллы**: покупка в магазине могла списать баллы без записи в `purchases` при ошибке; гонка «проверить баланс → списать»;
  цикл начисления падал целиком при одной ошибке; незакоммиченные начисления могли «съедаться» следующей транзакцией.
- **AFK**: падение цикла предупреждений при удалённом голосовом канале; `pending`-запросы не истекали; цикл умирал от любой ошибки.
- **CAPT**: двойное начисление при двух кликах; превышение лимита текста Components V2.
- **Анти-краш**: попытка снять `@everyone`/управляемые роли и упавший `HTTPException`; бан владельца сервера.
- **БД**: нет индексов и WAL; не закрывалась при остановке; запросы могли перемешиваться между корутинами.
- **Остальное**: `@everyone`-ответы в удалённый канал, тайм-ауты и баны без обработки `Forbidden`, `!setup` падал
  целиком из-за одной ошибки, длинные причины превышали лимит embed-поля (1024), `parse_when` возвращал прошедшую дату.

## Рекомендации по развитию
1. **Настройки в БД вместо `.env`** (ключи ролей/каналов уже в `settings`) — панель `/настройки` для руководства.
2. **Кэш привязок** (роли/каналы/`msg_afk`) в памяти с инвалидацией при `!setup` — сейчас каждый клик делает запросы к БД.
3. **Миграции схемы** (`PRAGMA user_version`) — сейчас новые поля надо добавлять вручную.
4. **Бэкапы**: `data.db` + `-wal`/`-shm` по расписанию (или `VACUUM INTO`).
5. **Аудит-лог в БД** для модерации (варны уже есть; баны/муты — только в канале логов).
6. **Ротация логов** в файл (`RotatingFileHandler`) и отправка критических ошибок владельцу в ЛС.
7. **Тесты** (pytest + моки discord.py) на сценарии заявок, магазина и CAPT — заготовки уже проверены офлайн.
8. **Ставки/лоты/сборы** — модуль `/mcl`, `/zonewars`, `/сбор`, если понадобится.
9. **Анти-краш по ролям**, а не по ID: доверять `role_owner`/`role_dep_owner` из настроек.
10. **Защита от фарма голоса**: учитывать реальное время в канале, а не фиксированные 60 секунд за тик.
